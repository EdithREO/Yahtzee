# 服务器物理测试

双击根目录 `test_server_physics.bat`，无头执行100次投掷。测试使用固定60帧步进加速运行，不代表实时服务器吞吐量。输出中的 failures 必须为0；碰撞计数来自 RigidBody3D.body_entered，内存快照是 Godot MEMORY_STATIC，不是整个进程工作集。

物理模块 `room/physics_world.gd` 复用原 addons/dice_3d、五颗骰子的定义和碰撞体、骰盘及四面墙、原始入场冲量和角速度、朝上面识别及逐颗恢复代码。每房间延迟创建独立物理世界，房间删除时释放。最多120秒模拟时间后明确失败，不使用随机点数代替失败。

房间已开始后，当前玩家的已认证 WebSocket 会话可发送 `{"type":"roll","request_id":1,"turn_id":1}`（请求序号及回合号必须使用当前值），无需点数、令牌或物理参数；服务端依据该连接已tests的座位鉴权。响应 `roll_started` 和 `roll_result` 广播给本房间在线玩家。并发重复投掷被拒，客户端不能指定点数。已接入网页动画与回合计分；请求仅允许当前玩家，详见 TURNS.md。

结果包含五颗骰子的稳定ID、朝上点数、世界位置、四元数旋转(x,y,z,w)、落稳时速度、耗时、恢复次数和碰撞数。落稳后冻结刚体保存位置；最新结果保存在物理模块及房间内存中。JSONL逐次日志位于 Godot user://physics_logs，启动时打印完整路径。失败记录也会保存。不会记录会话令牌。

执行过的100次检查和双客户端协议检查见本阶段进度及测试日志。未tests网页轨迹、跨设备物理播放、多房间负载、长时间运行、服务器重启后的结果恢复。未增加日志自动清理，长期运行需关注日志磁盘占用。
